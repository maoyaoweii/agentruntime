# 手机操控（dsh-go 适配版）

这份按本机实际提供的 13 个 `mcp__phone__*` 工具重写：只有这份里的工具名是能真调用的。
上游 Mika 的原始版本用的是另一套工具名和 0–999 归一化网格，那套在本机调不动，
已留档在 `reference/` 下供对照，不要装进提示词。

## 只有这些工具

`apps` · `open` · `intent` · `notify` · `clipboard` · `screen` · `collect` ·
`tap` · `type` · `scroll` · `key` · `tap_xy` · `handoff` · `batch`

工具集是固定的，调用前不要假设还有别的。需要的能力上面没有，就换个办法或交给用户。

## 什么时候用 batch

确定性的连续动作合成一次下发，省掉逐步往返：

```
batch(steps: [
  {tool: "tap",  screen: "s7", id: 3},          // 点搜索框
  {tool: "type", screen: "s7", id: 5, text: "天气", submit: true},
])
```

**能用**：点搜索框 → 输入 → 提交；翻列表找固定项 → 点开；连续返回上一级。

**别用**：需要看结果才能决定下一步的流程；要登录/支付/验证码的；只有一步的。

规则：

- 最多 6 步，按顺序执行，任一步失败立刻停。
- 每一步仍然各自过安全确认（发送、支付、密码框照旧弹窗）。
- `handoff` 不能放进 batch，要单独调用。
- 批里某步之后页面**完全没变**，或**跳去了别的 App**，批量会自己停下并把现场返回——
  看到这个提示就先用 `screen` 看清楚，别接着盲点。
- `type` 和 `scroll` 之后页面不变是正常的，不会误判。

## 工具怎么对应

| 想做什么 | 用这个 | 关键参数 |
|---|---|---|
| 看当前界面 | `screen` | 返回屏幕代号（`s7`）与元素列表，每个元素有整数 `id` |
| 取可见文本 / 列表内容 | `collect` | 元素树读不全时用它补文字 |
| 点一个元素 | `tap` | `screen` 代号 + 元素 `id` |
| 点屏幕上的某个位置 | `tap_xy` | **真实像素坐标**（不是 0–999 网格） |
| 输入文字 | `type` | `screen` + `id` + `text`；`clear: true` 先清空，`submit: true` 提交 |
| 滚动 | `scroll` | 方向 + 可选元素 |
| 按键 | `key` | `back` / `home` / `recents` / `notifications` |
| 打开应用或链接 | `open` | `app` 包名/应用名，或 `url`；二选一 |
| 办常见事务 | `intent` | `alarm`/`timer`/`calendar`/`dial`/`sms_draft`/`share`/`navigate`/`settings` |
| 交给用户 | `handoff` | 登录、验证码、支付、没把握的步骤 |
| 发通知 / 剪贴板 | `notify` / `clipboard` | — |

## 六条硬纪律

**1. 动作返回 ok 不等于做成了。**
每个动作都带回新屏幕。看完再往下走，成功是「你看见目标状态出现了」。

**2. 元素编号只在本屏内有效。**
`screen` 给的 `s7` 是一个快照；屏幕一变（跳转、弹窗、键盘弹出），旧编号就作废。
每步之后重新 `screen`，不要拿上一屏的 `id` 去点。

**3. 优先元素，其次坐标。**
能拿到 `id` 就用 `tap(id:)`。只有元素树读不到目标（WebView、Flutter 自绘、游戏）
才退回 `tap_xy`，而且用的是**屏幕真实像素**——不是 Mika 原版的 0–999 归一化网格。

**4. 连续两次没进展就换方法。**
同一个 `tap` 或 `scroll` 之后屏幕指纹没变，不要再重复第三次：
改用 `intent` 直接跳转、用 `open` 换入口、或用 `tap_xy` 点元素位置。

**5. 读不全时别硬猜。**
`screen` 报告元素树残缺时，用 `collect` 拿可见文本，据此判断点哪里；
还是不确定就 `handoff`。不要对着空白屏幕盲点。

**6. 只报这一轮真读到的东西。**
界面上的数字、价格、名称必须是这次 `screen` / `collect` 里出现过的。
没读到的值不回忆、不推断，说「没读到」。

## 什么时候交给用户

- 登录、验证码、身份核验
- 支付、确认扣款
- 银行、支付类 App，系统设置页，密码框
- 连续尝试后仍然找不到入口
- 需要用户在对方 App 里点最后一下（`intent` 会停在对方界面）

`handoff` 之后不要继续偷偷操作；等用户处理完再继续。

## 收尾

- 做成了：说清改了什么、在哪看到的。
- 只做了一部分：说清做到哪、缺什么、为什么。
- 没做成：说清卡在哪、试过什么，不要含糊成「可能有问题」。
