## 零、先说清楚 jev 是什么

这一轮之前，我对「jev」错了两次：

| 轮次 | 我的理解 | 做出来的东西 | 为什么错 |
|---|---|---|---|
| 任务 7 | 「一个通用决策模型」 | 17KB 文本意图分类器 | 把它当成一个模型产品，去「找一个」它 |
| 任务 10 | 「视觉模型的搭档」 | SmolVLM-256M | 把它当成 L2 视觉能力 |
| 任务 11 | 读原始文档术语表 | 本报告 | 前两次都是猜的 |

原始立项文档术语表的原文：

> **System-1 / Jev-like**：受限候选集合上的快速决策接口范式，不特指可本地部署的具体模型产品。

同一份文档对接口的验收要求：

> **System-1 接口**：候选动作输入 / 选择输出可回放；第一版本地规则可用，决策模型可替换。

拆开看就三句话：

1. 它是**接口范式**，不是可下载的模型 → 「找一个 jev 模型」这条路本身不存在。
2. 交付物是**候选进、选择出、可回放**三件事。
3. 第一版规则实现合法，但**必须留出模型实现的位置**。

所以 V1.0 的 `RuleBasedSystem1` 其实已经满足「第一版规则可用」；
缺的是「决策模型可替换」那一半——这一轮补的就是它。

> V1.4 的 SmolVLM 不是白做：它是 L2 视觉能力，文档里另有一节。
> 但它**不能算 jev 的交付**，这两件事不该混在一起说。

## 一、做成什么样

```
受限候选集合（Executor 给的合法候选，不可自由生成动作）
        │
        ├─ JevFeatures.extract()  → 10 维浮点特征
        │
        ├─ 权重点积               → 每个候选一个分数
        │
        ├─ argmax                 → 选中的候选
        │
        └─ softmax                → 置信度（分数接近则低，触发上层升级）
```

### 10 维特征

| # | 特征 | 计算方式 |
|---|---|---|
| 0 | `exact_match` | 标签 == 子目标 → 1 |
| 1 | `goal_contains` | 子目标包含标签 → 1 |
| 2 | `label_contains` | 标签包含子目标 → 1 |
| 3 | `overlap` | LCS(标签, 子目标) / len(子目标) |
| 4 | `clickable` | 节点 isClickable |
| 5 | `visible` | 在屏内且宽高非零 |
| 6 | `editable` | 节点 isEditable |
| 7 | `area_ratio` | 节点面积 / 屏幕面积（封顶 1） |
| 8 | `center_bias` | 1 - 中心点离屏幕中心的归一化距离 |
| 9 | `label_len` | len(标签) / 20（封顶 1） |

**为什么要单独一个 `JevFeatures` 类：** Python 训练端与 Java 推理端必须逐项一致。
字段顺序错一位，模型不会报错，只会「选得莫名其妙」——这类 bug 没有报错信息，
只能靠把定义收在一处来避免。

### 权重

| 特征 | 权重 | 解读 |
|---|---|---|
| `clickable` | **+3.28** | 可点击是最强信号 |
| `overlap` | **+2.87** | 字面重合率比「完全相等」更有用（标签常带空格/图标描述） |
| `goal_contains` | **+2.61** | 目标里出现了这个标签 |
| `visible` | **+2.12** | 屏外的不选 |
| `label_contains` | +1.32 | 标签里含目标（弱一些，容易命中长文本容器） |
| `editable` | +0.81 | 输入类目标需要 |
| `label_len` | +0.17 | 略偏好长标签 |
| `exact_match` | +0.14 | **被 overlap 覆盖了**，见下方说明 |
| `center_bias` | -0.03 | 几乎不起作用 |
| `area_ratio` | **-1.42** | 面积越大越不可能是目标（全屏容器通常只是布局根节点） |

`exact_match` 权重只有 0.14 不奇怪：完全相等时 `overlap` 必然为 1、`goal_contains` 也必然为 1，
三个特征高度共线，梯度会随便分配给其中一个。这说明**特征设计有冗余**，
但线性模型对共线不敏感，不影响选择结果。

## 二、训练与数字

| 项 | 值 |
|---|---|
| 脚本 | `tools/train_jev_decider.py` |
| 场景数 | 38（每个 3~6 个候选） |
| 覆盖难例 | 精确命中 / 部分包含 / 干扰项 / 同名多候选 / 屏外 / 不可点击 |
| 训练方式 | softmax + 交叉熵，梯度下降 |
| 产物 | `assets/models/jev_decider.json`（552 字节） |

| 实现 | 准确率 |
|---|---|
| 规则基线（选第一个可点击且标签非空） | 92.11%（35/38） |
| 线性决策器 | **97.37%（37/38）** |

**这两个数字都不可当真。** 它们是在训练集上算的，38 个样本划分留出集没有统计意义。
它只能回答一个问题：「特征设计是否包含了选择所需的信息」——答案是包含。
真实界面准确率必须用真机候选集重测，见第五节。

## 三、可回放：日志必须能复算

`replayLog()` 的输出结构：

```json
{
  "sub_goal": "发送",
  "model_version": "1.0",
  "features": ["exact_match", "goal_contains", "...10 项"],
  "weights": [0.13787, 2.60458, "...10 项"],
  "choice": "c1",
  "confidence": 0.83,
  "reason": "jev model v1.0, best=发送 score=12.34 conf=0.83 candidates=3",
  "candidates": [{"id": "c0", "label": "取消"}, "...全部候选"],
  "trace_available": true,
  "replay_rule": "argmax(dot(weights, features)) 应等于 choice",
  "trace": [
    {"id": "c0", "label": "取消",   "node_resolved": true, "features": ["...10 项"], "score": 1.23},
    {"id": "c1", "label": "发送",   "node_resolved": true, "features": ["...10 项"], "score": 12.31},
    {"id": "c2", "label": "输入消息", "node_resolved": true, "features": ["...10 项"], "score": 2.05}
  ]
}
```

**第一版是残缺的。** 最初只记了候选 id 和 label，没记各候选的特征向量——
那时外部要复算，还得拿到原始 `UiNode`（点击性、坐标、面积），等于不能回放。
「日志能看」和「日志能复算」是两件事，我把前者的完成度当成了后者。

现在补了 `trace`：拿 `weights` 与每行 `features` 做点积取 argmax，必须等于 `choice`。
这条已经落成测试 `replayTraceRecomputesChoiceOffline`——它真的在测试里重算一遍，
并对每行的 `score` 做一致性校验（误差 1e-3）。

**一个必须说清的代价：** `replayLog` 的签名只拿到 `Candidate`（id/nodeId/label），
拿不到 `UiNode`，所以没法在回放时重算。特征快照只能在 `decide()` 时存下来，
于是形成了「同一线程内先 decide 再 replayLog」的隐含约定。执行器正是这么用的；
跨线程或换候选集取用时，`trace_available` 会是 false 并给出原因
（`replayTraceRefusesMismatchedCandidates` 覆盖这两种情况），
**宁可说不可用，也不给出错位的数据**。

## 四、可替换性怎么验证的

| 断言 | 内容 |
|---|---|
| 同一接口 | `JevDecider` 与 `RuleBasedSystem1` 都实现 `System1`，可互换赋值后调用 `decide()` 不崩 |
| 失败可降级 | `fromAssets()` 对缺失/畸形权重返回 null，不抛异常（抛异常会拖垮 `Application.onCreate`） |
| 权重维度校验 | 权重数组长度 ≠ 10 时抛 `JSONException`，不回退成「长度不匹配也能跑」 |
| 元信息可查 | `describe()` 暴露版本、特征名、权重、训练场景数、准确率、备注 |

**降级路径必须自己承担失败**，不能把异常甩给启动流程——一个可降级的决策器不值得让 App 起不来。

### V1.5 新增的 16 项单测

| 用例 | 断言内容 |
|---|---|
| `featureDimensionMatchesTraining` | 特征维度 == 权重维度 == 10 |
| `exactMatchFeatureFires` | 完全匹配时 0/1/2/3 号特征取值正确 |

| `clickableAndVisibleAreEncoded` | 4/5 号特征随节点属性变化 |
| `centerBiasPrefersMiddleOfScreen` | 屏幕中心节点的 8 号特征 > 角落节点 |
| `areaRatioIsCappedForHugeContainers` | 全屏节点面积特征封顶为 1，不是 1.0 以上 |
| `lcsHandlesCommonSubsequence` | LCS 对「发送消息」「发消息」等给出正确长度 |
| `picksExactMatchOverNoise` | 4 个候选含 3 个干扰项时选中正确项 |
| `prefersClickableOverNonClickableDuplicate` | 同名两候选中选可点击的那个 |
| `handlesEmptyCandidateList` | 空候选集返回 choiceId=null、reason=no_candidates，不崩 |
| `confidenceDropsWhenCandidatesAreSimilar` | 两候选特征接近时置信度显著低于差异明显时 |
| `replayLogRecordsFeaturesAndWeights` | 回放日志含特征名、权重、候选、选择、置信度 |
| `replayTraceRecomputesChoiceOffline` | 用日志里的 weights × 每行 features 复算 argmax 等于 choice；逐行 score 一致（1e-3） |
| `replayTraceRefusesMismatchedCandidates` | 未调用 decide 或候选数不一致时 `trace_available=false` 且不含 trace |
| `bothImplementationsShareTheSameInterface` | 两个实现可互换赋值并正常决策 |
| `modelMetadataIsExposed` | `describe()` 的版本/场景数/准确率/备注非空 |

## 六、明确没做到的

| 项 | 状态 | 说明 |
|---|---|---|
| 真实界面准确率 | ❌ 未测 | 训练集是合成场景，与真实 App 的候选分布差距大 |
| 留出集 / 混淆矩阵 | ❌ 未做 | 38 个样本划分无统计意义 |
| 设备侧运行 | ⚠️ 未验证 | 无真机、无模拟器；只做到编译 + 产物核验 |
| 回放日志自包含 | ✅ 已做到（有代价） | 特征快照是实例状态，依赖同线程先 decide 再 replayLog；详见第三节末 |
| 回放日志落盘 | ❌ 未做 | 只在内存里拼 JSON，没有环形缓冲/导出通道，做不了批量离线评估 |
| 与 VLM 的链路 | ❌ 未通 | VLM 生成循环未联调，「VLM 描述界面 → System-1 选择」这条链还不通 |
| 候选集粗筛 | ❌ 未做 | 一屏上百节点时是 O(n) 全打分 |
| 多轮上下文特征 | ❌ 未做 | 缺「与上一步动作的空间关系」「历史点击偏好」「同名标签消歧」 |

**「未验证」= 代码写完了、编译过了、逻辑自洽，但没有在设备上跑过一次。**
这一栏不能算交付合格项。

## 七、下一步

1. **真机采集重训**——在真实 App 上跑一轮，把候选集与人工选择结果落盘，重训并补留出集。
   这是把 97.37% 变成有意义数字的唯一路径。
2. **回放日志落盘**——加环形缓冲与导出（每次决策一个 trace token，解除「同一线程」的隐含约定），
   才能做「跑一万次后离线批量评估」。
3. **接上 VLM**——VLM 生成循环联调后，把界面描述作为 `subGoal` 的补充上下文喂给决策器。
4. **特征扩展**——加「与上一步的空间关系」「同屏重复标签消歧」两维，覆盖多轮任务。
