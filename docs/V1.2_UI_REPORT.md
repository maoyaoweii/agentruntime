## 三、未验证项（不可算作通过）

界面类的改动，静态验证能覆盖的部分到这里就结束了。以下全部**未在设备上跑过一次**：

| 项 | 风险点 |
|---|---|
| 四个界面的实际渲染 | 配色对比度、文字截断、卡片间距、小屏适配，全都没看过 |
| 状态栏内边距 | `applyStatusBarPadding` 靠读 `status_bar_height`，刘海屏/挖孔屏表现未知 |
| 悬浮球拖动与贴边 | `updateViewLayout` 的坐标边界、`FLAG_LAYOUT_NO_LIMITS` 副作用未验 |
| 悬浮面板输入法 | 键盘弹出时面板是否被顶起、`SOFT_INPUT_ADJUST_RESIZE` 在 overlay 窗口是否生效 |
| 悬浮球遮挡 | 是否挡住其他 App 的关键按钮，没有视觉确认 |
| QS 磁贴 | 需用户手动添加到快捷设置面板；磁贴图标与副标题显示未验 |
| 桌面快捷方式 | 长按图标是否出现三个入口，未验 |
| 音量键长按 | 部分 ROM 抢占音量键；`onKeyEvent` 消费时机未在真机确认 |
| 前台服务存活 | Android 14 的 specialUse 限制、厂商省电策略杀进程 |
| 通知 | 渠道分组、常驻通知的"控制台"动作按钮，未验 |
| 深色模式 | 固定浅色主题，在深色系统下观感未知 |

## 四、给下一次验证的建议顺序

1. 装 APK → 主页是否正常渲染，五枚徽章取值是否正确
2. 开无障碍 → 徽章是否变绿，控制台是否能收到 `TaskBus` 事件
3. 主页点「观察环境」→ 控制台应逐步打印进度，结束后主页"最近任务"应显示成功徽章
4. 授权悬浮窗 → 开启悬浮球 → 拖动测试贴边 → 点击展开面板 → 输入目标执行
5. 下拉通知栏 → 编辑磁贴 → 添加 Agent 磁贴 → 点击是否进控制台
6. 长按桌面图标 → 三个快捷方式是否出现
7. 长按音量下键 → 悬浮球是否弹出；短按是否仍能正常调音量
8. 深色模式下看一遍四个界面

## 五、诚实结论

这一轮把「引擎外壳」补成了看起来像个 App 的东西：4 个界面、悬浮球、4 种唤起方式、实时日志。

但**我对它的外观一无所知**——没有设备，一行代码都没在屏幕上渲染过。配色是按设计常识定的，间距是按 8dp 网格排的，长文案是否截断、按钮是否够大、悬浮球会不会挡手，全部只有代码层面的把握。

按项目规范，这些一律标注「未验证」，不写成「已实现」。
