## 一、这一轮解决的核心问题：模拟器真的跑起来了

历史记录（`EMULATOR_SETUP.md`、任务 12、补充 2026-10-23）里模拟器一直起不来，两个独立阻塞：

1. 作者机器（Windows/AMD）BIOS 里 SVM 被关，`-accel-check` 报 6，纯 TCG 下 qemu CPU 恒为 0、设备永远 `offline`；
2. 带窗口启动缺 `opengl32sw.dll`，启动器自身崩溃。

**本轮在 Linux 沙箱上用同一套 TCG 路线把模拟器真正拉起来了**
（无 `/dev/kvm`、无硬件虚拟化）：

| 步骤 | 结果 |
|---|---|
| `sdkmanager emulator "system-images;android-30;aosp_atd;x86_64"` | ✅ 安装（镜像 3.2GB） |
| `avdmanager create avd -n agent_api30 -k ... --device "Nexus 5"` | ✅ 创建 |
| `emulator -avd agent_api30 -no-window -no-audio -no-boot-anim -no-snapshot -accel off -gpu swiftshader_indirect -memory 2048 -cores 2 -wipe-data` | ✅ **启动成功** |
| `adb shell getprop sys.boot_completed` | ✅ 约 3.5 分钟后得 `1` |
| `adb install agent-debug.apk / agenttestapp-debug.apk` | ✅ Success |
| 稳定运行时长 | ✅ 连续 35+ 分钟存活（qemu RSS ≈ 3.3GB） |

**结论：TCG 软件模拟在 Linux 上可用；此前 Windows 上的失败是宿主环境（固件/启动器）差异，不是 TCG 本身不可用。**

## 二、APK 安装与无障碍绑定

- `com.agentruntime.agent`（debug，v1.6.0/vc7，36.9MB，arm64+x86_64）安装成功，`MainActivity` 正常启动，无 FATAL。
- 无障碍服务 `com.agentruntime.service.AgentAccessibilityService` 经
  `settings put secure enabled_accessibility_services` + `accessibility_enabled=1` 绑定：
  `dumpsys accessibility` 显示 **Bound services**、`Crashed services:{}`，capabilities=169（含截图与手势位）。

### 观察到的一个环境行为（非代码缺陷）
安装/卸载 APK 会让 Agent 进程被杀，无障碍管理器随即把该服务标成 **Crashed**，
且清除设置再重设也无法恢复绑定——**只有 reboot 设备能清掉这个 crashed 状态**。
这是 ATD 镜像 + 无障碍管理器的既有行为（历史「问题 32」的同类波动）。
规避办法：**安装后重启一次设备再绑定**，绑定后不再 force-stop Agent 进程。

## 五、本轮修复的真实设备缺陷

在真机/模拟器上跑出来的问题，逐条修复（详见 `PROJECT_CHANGELOG.md` [任务 13]）：

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | ADB 下发任务时 `wait_for` 全部超时 | `TaskExecActivity` 一直占前台，`getRootInActiveWindow()` 只返回 Agent 自己的窗口，看不到被测应用 | `TaskExecActivity` 执行前 `moveTaskToBack(true)`（可用 `behind_after_launch=false` 关闭），让目标应用成为活动窗口 |
| 2 | 内置浏览器页面空白、`read_page` 报 `NO_PAGE_TEXT` | 截图确认为 `net::ERR_CLEARTEXT_NOT_PERMITTED`：Android 9+ 默认禁明文 HTTP | 新增 `res/xml/network_security_config.xml`，**只对 localhost/127.0.0.1/10.0.2.2 放开明文**，其余域名仍强制 HTTPS；Manifest 挂 `android:networkSecurityConfig` |
| 3 | 截图失败时无声无息，无法诊断 | `ScreenCapturer` 把所有异常吞成 `return null` | 增加 `Log.w`（异常类型/超时/onFailure errorCode），失败原因进得了 logcat |
| 4 | 单测在 root 下误报 `FILE_READ` 而非 `FILE_READ_FAILED` | JVM 用 POSIX 权限位，root 无视 mode 000；Android 的 `Os.access` 亦同 | 生产代码改用 `canRead()` 判定；用例改为断言「脱敏不泄露路径」这一真正契约，不依赖运行身份 |
