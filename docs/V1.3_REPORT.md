## 一、内置模型：这次是真的"装好了"

| 项 | 值 |
|---|---|
| 模型类型 | 多项式朴素贝叶斯（字符 uni/bi-gram） |
| 训练语料 | 12 个意图 × 30±5 条中文说法，共 360 条 |
| 训练/留出 | 312 / 48 |
| **留出集准确率** | **93.8%（45/48）** |
| 词表 | 457 token（只保留出现 ≥2 次的） |
| 权重体积 | **17.0 KB** |
| 推理位置 | 设备内，纯 Java，无网络 |

### 为什么不是大模型

真跑一个视觉语言模型需要：onnxruntime-android（+20MB）、量化权重（250MB~1.2GB）、
自己实现 tokenizer 与自回归解码、真机内存压测。这四件事在本环境（无设备、无权重）一件都验证不了。
硬写一个"看起来接了大模型"的壳，比不做更糟。

所以做的是**能力范围内的真模型**：17KB、随 APK 安装、毫秒级、可被单测证伪。

### 它能做什么

规则层靠关键词命中，说法一换就失效（"把它截下来"命中不了"截图"）。这个模型做浅层泛化：

| 输入 | 预测 | 置信度 |
|---|---|---|
| 帮我截个屏 | screenshot → sys.screenshot | 可用 |
| 看看当前设备环境怎么样 | observe → sys.observe | 可用 |
| 打开闹钟 | open_clock → sys.open_clock | 可用 |
| 在笔记里新建一条记录 | create_note（需参数，不直接执行） | — |
| zzz qqq xxx 1234 | 低置信度，拒绝 | — |

### 它不能做什么

- 不做推理链，只做单句意图分类
- 需要参数的目标（写笔记的标题正文、发消息的内容、视觉点击的目标）**返回 null 交给上层**——
  不猜参数，因为用错参数跑一遍比不跑更糟
- 语料是手写的 312 条，口语长句的置信度会明显下降

## 二、输出格式：从"各写一套"到"唯一入口"

改造前，三个适配器各自用 `indexOf('{') + lastIndexOf('}')` 抽 JSON。模型一次输出两个对象时，
这会切出 `{"a":1} 然后是 {"b":2}` 这样的非法片段。

现在统一为三阶段：

| 阶段 | 能力 | 明确不做 |
|---|---|---|
| 抽取 | 括号计数 + 字符串感知（跳过 `"..."` 内的 `{}`）；处理 markdown fence、前后废话、多对象 | 不猜缺失字段 |
| 修复 | 去注释、去尾逗号、全角引号转半角 | 不补引号、不修错键名 |
| 校验 | task / action / grounding 三套严格 schema | 不把畸形数据"修好" |

最后一条是刻意设计：**把错误数据修成合法的错误任务，比直接失败危险得多。**

单测覆盖 12 项：fence 剥离、多对象取首个、字符串内花括号、尾逗号、全角引号、
无 JSON 时报错、grounding 四种形态、action 三种形态。

## 三、底层工具与输入法

### 系统底层（+11 动作，动作总数 40）

| 动作 | 权限 | 未授权时的行为 |
|---|---|---|
| set_volume / get_volume | 无 | — |
| set_brightness | WRITE_SETTINGS | 返回 NEED_PERMISSION，界面给跳转 |
| clipboard_set / get | 无 | — |
| media_key | 无 | 未知键返回 BAD_MEDIA_KEY |
| vibrate | VIBRATE | 无振动器返回 NO_VIBRATOR |
| open_settings_page | 无 | 未知页返回 BAD_SETTINGS_PAGE + 白名单 |
| list_apps | QUERY_ALL_PACKAGES | — |
| read_file / write_file | — | 路径出界返回 PATH_NOT_ALLOWED |

**文件只给 app 私有目录**，路径解析为 canonical path 后校验前缀，防 `../` 穿越。
不申请 `MANAGE_EXTERNAL_STORAGE`——那是这个 App 不该要的权限。

### 输入法（+3 动作）

`AgentImeService` 是极简 InputMethodService：无键盘，只有 40dp 提示条，
通过 `InputConnection.commitText` 注入。

| 动作 | 说明 |
|---|---|
| ime_commit | 向当前焦点输入框注入文本 |
| ime_read | 读回当前输入框内容 |
| ime_key | enter / delete / search |

它是兜底通道：默认仍走无障碍 `input_text`，只有在 WebView 内部框、游戏、自绘控件里才需要切过来。
