## 三、过程中发现并修复的问题

### 3.1 中文路径导致单元测试无法运行（阻塞级）

- **现象**：`assembleDebug` 正常，`testDebugUnitTest` 报 `ClassNotFoundException: com.agentruntime.AgentCoreTest`；`build/intermediates/javac/debugUnitTest/.../AgentCoreTest.class` 确实存在。
- **排查**：把同一份工程复制到 `E:\agentrt_probe`（纯英文），测试立刻通过 → 排除代码问题。再试 `mklink /J E:\agent_rt <中文路径>`，仍失败，Gradle 报告里的路径还原成中文 → junction 骗不过 Java 的 canonical path 解析。
- **处理**：构建与测试改在 `E:\agentruntime` 进行，源码同步回中文 workspace。
- **影响**：这是本轮最耗时的排查（约 8 分钟），也是 README 开头单独强调的原因。

### 3.2 `GRADLE_OPTS` 中的 `|` 触发 xargs 断言

- **现象**：加入 `-Dhttp.nonProxyHosts=localhost|127.0.0.1` 后，构建输出 `assertion "bc_ctl.arg_max >= LINE_MAX" failed: file "xargs.c"`，随后插件解析失败。
- **处理**：去掉含 `|` 的参数，只保留 `proxyHost/proxyPort`。

### 3.3 首次失败结果被 Gradle 缓存

- **现象**：配好代理后仍报 `Plugin [id: 'com.android.application', version: '8.6.1'] was not found`，10 秒内失败且无任何网络错误。
- **处理**：`--refresh-dependencies` 强制重查，之后正常。

### 3.4 `com.sun.net.httpserver` 不在 Android 编译 classpath

- **现象**：单测 import 后 javac 报「程序包不存在」。
- **处理**：改用 `java.net.ServerSocket` 手写最小 HTTP 服务。副作用是更贴近真实约束——Android 上本来就只有 `java.net`。

### 3.5 CSS 选择器白名单误伤合法选择器

- **现象**：单测 `selectorAcceptsCommonCssForms` 失败，`div.result > span` 被拒。
- **原因**：初版为防注入把 `>` 也禁了，但 `>` 是合法子选择器符号。
- **处理**：只禁引号、分号、`` ` ``、`<`；放宽后仍能拒绝 `#btn');alert(1);//` 与 `div;rm -rf /`。

### 3.6 `web.click_selector` 技能初版用 `tap_xy` 占位

- **发现**：写技能 JSON 时意识到这会在真机上真的点左上角。
- **处理**：新增 `page_click` / `page_find` 两个动作，技能改为真实调用。
